**The core distinction:** A real memory-mapped **read** can access source data without generating native IN_ACCESS. A real MAP_SHARED memory-mapped **write** can change on-disk bytes without generating native IN_MODIFY during the mapped store. IN_CLOSE_WRITE may still be generated at **final writable reference release**, which need not coincide with the original descriptor close if a writable mapping persists. In contrast, a private MAP_PRIVATE/COW mapping can contain different process-visible bytes without changing the underlying file at all. Consequently neither a quiet interim queue nor a simple count of IN_MODIFY events is sufficient to prove protected files were not written.

**Do not overclaim the negative controls.** These events were separately probed on newly generated PUBLIC /tmp Linux native fixtures, and the source-defined tests are submitted in strict draft branches for exact-head full CI verification. They do not assert every filesystem/mount/kernel behaves identically or a mapped write always yields a particular notification. Positive continuing CLOSE_WRITE evidence in the tested file-close paths is an observed kernel event, not an independent protected OS no-write enforcement guarantee. The unchanged evaluator returns exactly **status=BLOCKED**, **can_authorize_dispatch=false**, and **independent_os_proof_verified=false** on genuine source write receipts regardless of source bytes later being restored.

**Watch identity and safety:** In every case, the original ONESHOT subscription is deliberately unsafe **test-only** code on a separate native descriptor. Actual unchanged `scripts/dec677_disposable_inotify_events.py::_start_watch` installs continuously watching source+original-parent mutation subscriptions **without ONESHOT**. The committed runtime is not modified here. Tests which use source O_RDONLY data access close independent read-witness descriptors **before** incidental content-verification reads; tests which enumerate watched directories close positive read-event witnesses **before** final `scandir` inventories, to prevent observer-induced extra events. All fixtures stay in generated disposable PUBLIC /tmp paths.
