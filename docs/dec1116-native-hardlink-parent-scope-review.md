**Key identity distinction:** A regular-file inotify watch follows the inode irrespective of which hard-link pathname triggers a content change; its event has no child basename. A directory inotify watch sees child events only for entries **within that watched directory**. A hard-link alias outside the watched parent is **not** a child of that parent even when it names the exact same watched source inode. Therefore, outside-alias writes produce source-inode events and outside-directory named events but not original-parent named events. An original-parent-only event stream cannot enumerate every hard-link pathname through which a watched source was modified.
