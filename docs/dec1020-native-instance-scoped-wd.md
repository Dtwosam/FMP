# DEC-1020 — Inotify watch descriptors are scoped to their owning instance

**DRAFT / NEVER MERGE / NEVER PROMOTE.** One-commit native Linux test/documentation child of DEC-1019/#1240, operating only on generated disposable public `/tmp` files.

Two genuinely independent Linux `inotify_init1` instances call the existing dual source+parent witness helper on the SAME generated public source and directory in the SAME watch registration order. Linux can allocate identical numeric source WD values and identical numeric parent WD values in both instances. This is expected: a watch identity is **(inotify instance, watch descriptor)**, not the bare integer WD or the watched pathname.

Native `inotify_rm_watch(second_fd, first_source_wd)` deliberately passes the numerical source WD obtained from the first instance to the **second FD**, demonstrating that Linux resolves the number in the **second instance's own WD namespace**. A real `IN_IGNORED` appears on the second instance; the first instance receives no invalidation and retains its full source+parent subscriptions. Distinct-byte public writes and later restoration are witnessed on both source and parent WDs of the first FD, but only the named parent WD of the second FD. The unchanged evaluator remains `BLOCKED`, exact `can_authorize_dispatch=false` and `independent_os_proof_verified=false`. Source/parent dev/inode/mode, restored bytes, one-name bounded inventory and both native FD closures are checked. A standalone native Linux probe confirmed equal WD integer values across independent instances, local-only `IN_IGNORED`, and the asymmetric real write streams.

This adds one source-defined Linux regression for **667** total. Numeric WD equality does not establish shared observer provenance; this complements DEC-1018's `dup` example in which two different FD integers **do** refer to one shared instance.
