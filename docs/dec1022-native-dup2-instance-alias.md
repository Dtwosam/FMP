# DEC-1022 — dup2 converts two independent inotify FDs into one shared instance

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit generated-public Linux regression/documentation child of DEC-1021/#1242.

Start with TWO truly separate native `inotify_init1` descriptors, each holding a genuine source+parent subscription to the same disposable public `/tmp/sample`. A real changed-byte write produces separately readable source and named parent events on each FD. Calling `os.dup2(primary_fd, second_fd)` then atomically **closes the second FD's original independent inotify instance** and replaces it with an alias of the **primary instance** while retaining the second numeric FD value. A subsequent real public source byte restoration produces a SINGLE shared queue: draining via second_fd leaves primary_fd empty.

Native `inotify_rm_watch(second_fd, source_wd)` now removes the primary instance's source watch, yielding `IN_IGNORED` readable on the primary FD; the former second instance no longer exists. Later genuine public source write/restore activity reaches only the primary's surviving parent WD, despite two different FD integers having existed just before. Closing the aliased second FD leaves the primary open but **cannot resurrect independent historical coverage**. The unchanged evaluator stays `BLOCKED`, `can_authorize_dispatch=false`, `independent_os_proof_verified=false`. The regression verifies the original source/parent device, inode, mode, byte restoration, one-entry bounded inventory and explicit native FD closure.

A separate kernel probe on disposable public Linux files confirmed initial independent queues, `dup2` replacement, shared queue consumption, and shared source-watch invalidation. This adds ONE native Linux method, bringing the draft stack to **669**. Contrasts with DEC-1018's non-closing `os.dup` alias and DEC-1021's equal numeric WD mapping between different independent instances. An unchanged numeric FD value is not evidence that its kernel inotify instance is unchanged.
