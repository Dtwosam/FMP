## Security interpretation

A protected source being absent from its original pathname, having **link count zero**, held only by a read-only descriptor, or having a writer FD reported closed is **insufficient evidence by itself** that the original inode cannot still be modified. Linux can retain an unlinked inode through open file descriptions, and a shared duplicated or procfs-reopened description can continue valid mutation after unlink. Procfs availability/permissions and filesystem behavior may differ by runner; this ledger records genuine tested Linux observations, not a universal guarantee. When a source is in its last-link-unlinked-but-open state, the original inode source WD and original directory parent WD can still report true MODIFY events for the removed dentry. Source DELETE_SELF/IGNORED arrives at real inode retirement, not necessarily at path unlink. Source integrity needs independently OS-enforced denial, not inotify detection or timing assumptions.

Every executable regression asserts actual kernel buffer bytes, genuine independently drained source and original-parent watch identity, accurate generated PUBLIC source snapshots or open-FD reads, and unchanged `scripts/dec677_disposable_inotify_events.py::_evaluate` returning **status=BLOCKED**, **can_authorize_dispatch=false**, **independent_os_proof_verified=false**. The isolated source-only ONESHOT remains an intentionally unsafe **test-only** negative control which expires on the first actual MODIFY→IGNORED; unchanged real continuing two-watch helper catches later native events as long as the kernel inode watch remains installed. Disposable source deletion is deliberate only for tests specifically verifying final unlink; it is **not** a recovery of the same original inode or authorization to operate on protected data.
