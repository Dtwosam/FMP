## Access control and event distinctions

1. **Original inode bytes versus mapping memory.** MAP_SHARED writable data writes are independently verified through actual original `pread` or freshly opened original-source reads; MAP_PRIVATE COW private bytes are contrasted with unchanged original inode contents. Equal final bytes do **not** prove absence of earlier mutation.
2. **Time of permission check.** Mode 0444 created by fchmod is a real inode-metadata change and emits **IN_ATTRIB**. But an already opened writable description or existing writable mapping can survive that mode downgrade. A newly acquired O_RDONLY FD's failed ftruncate shows denial for *that FD only*, not for the previously writable mapping or descriptor.
3. **Time of close.** An `os.close` of a writable descriptor need not emit CLOSE_WRITE when a writable MAP_SHARED mapping still holds a live backing reference. CLOSE_WRITE can arrive on final unmap. An event-positive CLOSE_WRITE also does not necessarily imply bytes changed (DEC-1261 #1482).
4. **Limits of inotify.** Genuine original source and named-parent watches detect native ATTRIB and CLOSE_WRITE for these cases, but may report no MODIFY for real mmap changes—even when the watcher is continuous and fully working. The intentionally unsafe test-only MODIFY|CLOSE_WRITE|ONESHOT can expire on CLOSE_WRITE long after the earlier invisible data writes.
5. **Authorization result.** Every executable native regression feeds unchanged `scripts/dec677_disposable_inotify_events.py::_evaluate` accurate generated PUBLIC original-source snapshots and genuine independently drained raw event buffer bytes; all changed-original-source states return **BLOCKED, can_authorize_dispatch=false, independent_os_proof_verified=false**. No detection trace, mode bit, descriptor count or final checksum can substitute for independent OS-enforced denial.
