The matrix separates **open-time data loss**, actual data-write syscall outcomes, **descriptor access mode**, actual **final bytes and file length**, original/source+named-parent inotify watch identities and event timing. A closing **IN_CLOSE_NOWRITE** does **not** imply an earlier open could not truncate. A no-op ftruncate can produce positive MODIFY even when bytes remain unchanged. A rejected read-only ftruncate is not evidence that a distinct O_RDONLY|O_TRUNC open would be harmless.
