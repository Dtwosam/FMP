### Security implications

- **Unlinked pathname and `st_nlink=0` are not independent no-write protection.** Linux open descriptions, procfs reopening and memory mappings can keep the original inode accessible and writable after its only name disappears.
- **Even continuously installed native inotify cannot detect all MAP_SHARED memory writes.** Changed actual inode bytes can be flushed and restored while native original source+named-parent `IN_MODIFY` queues remain empty. Native eventual CLOSE_WRITE can arrive only after final mapping unmap, not necessarily on the last Python `os.close`.
- **MAP_PRIVATE event silence means something different.** The userspace mapping's COW memory can differ from its original backing file while independent actual original inode `pread` remains unchanged. A mapping's changed bytes alone are not proof of original-source mutation. Both modes must be tested against *actual original inode bytes*, not simply native events.
- **An unsafe source MODIFY|CLOSE_WRITE|IN_ONESHOT is not continuous monitoring.** It can expire on first real CLOSE_WRITE even after byte-quiet contents, or remain armed throughout silent mmap writes; independent original continuous source+parent helper is a limited diagnostic observer, not OS-enforced access denial.
- Every regression's unchanged `scripts/dec677_disposable_inotify_events.py::_evaluate` remains **can_authorize_dispatch=false**, **independent_os_proof_verified=false**; genuine modified-source states must be **BLOCKED**. A true no-observed-write MAP_PRIVATE state may be `LOCAL_DISPOSABLE_WITNESS_UNVERIFIED` but is **never authorization**.
