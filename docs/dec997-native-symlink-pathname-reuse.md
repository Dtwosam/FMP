# DEC-997 — Symlink pathname reuse cannot preserve watched-inode identity

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit generated-public Linux test/documentation child of DEC-996/#1217.

The new control watches an actual disposable `public-alias` symlink inode with native `IN_DONT_FOLLOW | IN_MOVE_SELF | IN_DELETE_SELF | IN_MASK_CREATE` alongside existing generated source+parent watches. Renaming that alias to `public-moved-alias` preserves the **original symlink inode and its original WD**; the parent emits genuine matching-cookie `IN_MOVED_FROM` and `IN_MOVED_TO`, and the link WD emits `IN_MOVE_SELF`. The unchanged two-WD parser must fail closed on extra link-WD records.

While that original inode remains accessible at its new name, creating a second symlink at the original pathname creates a **different** symlink inode. It can be registered with a new create-only `IN_DONT_FOLLOW` watch on the same native FD. Unlinking the moved original emits `IN_DELETE_SELF` and `IN_IGNORED` for its original WD **without invalidating the new link WD**; unlinking the newly recreated alias later invalidates the second WD. This proves identical pathname spelling is not continuous watcher identity. It does not rely on guessing or requiring WD number reuse.

After both aliases are removed, the original regular-file source+parent watches continue to observe real public changed-byte writes and restoration, and the unchanged evaluator remains `BLOCKED` with exact `can_authorize_dispatch=false` and `independent_os_proof_verified=false`. Final source/parent device, inode, mode, fixture bytes, one-entry inventory and native FD closure are verified. A standalone native Linux probe reproduced the move/create/invalidation record sequence before the test was authored.
