**Three independent dimensions:** A real IN_MODIFY can accompany **unchanged contents** (KEEP_SIZE preallocation), **changed contents with unchanged file size** (PUNCH_HOLE|KEEP_SIZE, ZERO_RANGE|KEEP_SIZE), or **changed contents and file size** (ZERO_RANGE without KEEP_SIZE). A rejected unsupported or invalid flag combination produces no mutation event, but an ordinary writable FD close still creates CLOSE_WRITE even if the file's bytes never changed. Therefore neither event presence nor file-size equality alone proves the protected source's data changed or stayed unchanged.
