**Do not conflate these signals.** Linux inotify MODIFY indicates a kernel-reported modification operation, not whether the **existing actual bytes** differ afterward. Even a second zero-range on content that is already all zero, or a hole punch/zeroing range wholly beyond EOF, can generate MODIFY. Conversely, a plain allocation beyond EOF **without** KEEP_SIZE may extend the file from 21 bytes to 128 while preserving its original prefix and exposing an all-zero gap. A successful syscall, actual file bytes, logical size, inode/link identity, extent allocation, and event identity are independently meaningful evidence. No combination of disposable event receipts by itself proves OS-enforced protected annual no-write.
