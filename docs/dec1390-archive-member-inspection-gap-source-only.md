# DEC-1390 — ZIP archive member review is separate from byte digest matching

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit child #1613 DEC-1389 at `9618d424e98e9307af9137d206699ebd45efa2df`. Adds 11 source/synthetic test methods (**1,197 proposed source-defined methods**).

The tracked annual preflight (predecessor freeze) and 18-cell job download GitHub artifact ZIPs and compare each archive's SHA-256 bytes with a configured digest **before** calling `unzip -q` into checkout-relative staging directories. That digest comparison detects changes relative to the configured blob bytes. It does **not**, by itself, prove safe archive member names, non-symlink members, non-overlapping extraction names, independent publisher authenticity or containment of the resulting extracted data under the intended OS root. Source review finds no explicit `zipinfo`/`unzip -Z`/`unzip -l` entry-listing step before the observed `unzip` commands; this does **not** demonstrate that the installed unzip implementation can be exploited, because the actual ZIPs were not inspected or extracted.

The new test file creates small **in-memory-only** ZIP fixtures and an illustrative pre-extraction member inspector which rejects absolute, parent traversal, backslash, symlink, and normalized duplicate names. It confirms that **even a byte-perfect SHA-256 match to a caller-supplied expected digest can accompany a structurally hazardous synthetic member list**. No archive is extracted, no filesystem path is written, no real historical artifact is fetched and the illustrative inspector is deliberately **not installed** in annual execution or called on protected sources. Real validation would also need the selected platform's extractor behavior, size limits, path containment, symlink/hardlink controls, adversarial release properties, trusted archive origin and independent OS custodians.
