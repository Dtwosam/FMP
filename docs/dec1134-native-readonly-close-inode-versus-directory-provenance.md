**Identity is separate from location.** A file watch binds to an inode, so a read-only close through `outside/alias` generates the same **unnamed** source-inode CLOSE_NOWRITE type as one through `parent/sample`. A directory watch reports events for **its own entries**; only an outside-directory watcher can attach `alias` as the name of the external pathname. A read-only close on an unrelated sibling instead reports a **named** event to a suitably subscribed parent watcher and does **not** generate a source-file self-event. These are real native Linux kernel receipts, not reconstructed event stories from final snapshots.

**Original first-event loss is strictly test-only.** Each alternative original one-shot deliberately subscribes to `IN_CLOSE_NOWRITE` as well as mutation categories. The first real read-side close consumes that original subscription, yielding `IN_IGNORED`. It can no longer record later source writes, despite its initial MODIFY/CLOSE_WRITE subscriptions. The separate real normal **continuing source+parent** helper remains registered, excludes CLOSE_NOWRITE and positively witnesses genuine subsequent changed-byte and restoring writes through `sample` as **unnamed source MODIFY/CLOSE_WRITE plus named original-parent MODIFY/CLOSE_WRITE(sample)**. The unchanged evaluator on those real independent unsafe writes returns exact `status=BLOCKED`, `can_authorize_dispatch=false`, and `independent_os_proof_verified=false`.

**Do not infer absence of metadata changes.** Neither an O_RDONLY open+close nor a source-content-neutral operation is a universal metadata-neutral claim: atime may depend on filesystem and access behavior. These tests assert source-content bytes and bounded inventory are unchanged after the read-close stage; they do not claim all timestamps stay equal. A named `CLOSE_NOWRITE` is not a content-change notification, and a subsequent identical final digest cannot certify the absence of intervening writes.

All operations use genuinely disposable PUBLIC /tmp fixtures. DEC-1133's two names are hard links (nlink=2) and explicitly a **negative local control**: the actual admissible snapshot helper independently rejects multiply linked source inodes. None of these cases demonstrates a deployed observer defect or an independently OS-enforced protected no-write policy. Actual unchanged `scripts/dec677_disposable_inotify_events.py::_start_watch` registers **continuing source+parent mutation watches without IN_ONESHOT**.
