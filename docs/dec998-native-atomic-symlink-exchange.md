# DEC-998 — Atomic RENAME_EXCHANGE swaps symlink pathnames, not watched inodes

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit Linux regression/documentation child of DEC-997/#1218.

The generated-public kernel control creates two symlinks pointing to the same disposable regular source file. Both symlinks receive their own actual `IN_DONT_FOLLOW | IN_MASK_CREATE | IN_MOVE_SELF | IN_DELETE_SELF` watches, alongside the original source+parent WDs on the same inotify FD. A native `renameat2(RENAME_EXCHANGE)` atomically exchanges the **directory-entry pathnames** while preserving the two different **symlink inodes** and existing WD registrations. Real Linux emits two paired `IN_MOVED_FROM`/`IN_MOVED_TO` cookie pairs on the parent, and `IN_MOVE_SELF` on both symlink-inode watches. Neither symlink watch is immediately invalidated by the exchange.

Unlinking the first pathname **after the exchange** invalidates the watch initially registered on the *other* pathname's inode; unlinking the second pathname invalidates the first. The test checks the exact native `IN_DELETE_SELF` and `IN_IGNORED` records, distinct inode identities, nonzero rename cookies with proper move pairing, and original source+parent watch continuity. Native extra link-WD records must not be interpreted as well-formed input to the unchanged two-WD observer; its evaluator must return `BLOCKED` with exact `can_authorize_dispatch=false` and `independent_os_proof_verified=false`. Later genuine public source writes/restore remain visible, and final sample/parent device, inode, mode, original bytes, bounded inventory, and FD closure are checked.

A separate kernel probe reproduced the exchange, cookie, inode-swap and watch-invalidation sequence. One new Linux source-defined method gives **652** across the strict draft stack.
