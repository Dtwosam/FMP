**Verify event time and pathname, not just final bytes.** Linux source-file inotify event names are empty because that watch binds to the inode. Directory watches see events for **their own entries**, including the target's original parent for a followed symlink and the outside directory for a hard-link alias. Normal O_RDONLY OPEN and read-only CLOSE are separate native events from ACCESS on an actual byte-returning read. A source may be accessed while its byte values and even timestamps remain unchanged. A successful O_PATH lookup is not content access. Error ELOOP on O_RDONLY|O_NOFOLLOW is deliberate fail-closed link resolution.

**Protect test-observer provenance.** Watching directory OPEN/ACCESS/CLOSE_NOWRITE while calling `os.scandir` on that watched directory itself generates legitimate read-side **IN_OPEN|IN_ISDIR, IN_ACCESS|IN_ISDIR, IN_CLOSE_NOWRITE|IN_ISDIR**. This explains exact-head historical FAILED #1365–#1367; correction #1368 strictly closes the outside witness before final inventory, and #1369–#1370 positively cover the directory scanning lifecycle. In read tests, independently subscribed positive read-event witnesses must be closed before incidental `read_bytes` verification to avoid polluting the expected stream.

**No false production authorization.** The unsafe IN_ONESHOT watchers are deliberately alternative, isolated native **test-only** subscriptions. Real unchanged `scripts/dec677_disposable_inotify_events.py::_start_watch` continuously monitors **source+original-parent mutation** without ONESHOT. Later genuinely changed-byte and restoring writes are still captured by actual continuing source+parent MODIFY/CLOSE_WRITE; the unchanged evaluator remains `status=BLOCKED`, `can_authorize_dispatch=false`, `independent_os_proof_verified=false`.
