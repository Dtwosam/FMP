# DEC-1025 — A duplicate FD can change the original inotify watch mask

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit generated-public Linux regression/documentation child of DEC-1024/#1245.

An original disposable public source+parent inotify instance is duplicated with `os.dup`, and a separate independent source+parent instance is registered as control. Native `inotify_add_watch(dup_fd, sample, IN_MASK_ADD | IN_OPEN)` acts on the SAME watched source inode inside the ORIGINAL kernel inotify instance, returning its unchanged source WD. The independent second instance does not receive this mask mutation.

A genuine public write to `sample` now produces an additional native `IN_OPEN` action on the original source WD, along with actual source `IN_MODIFY`/`IN_CLOSE_WRITE` and parent named write events. The unchanged original two-WD parser must **fail closed** on the unexpected `IN_OPEN` event (`well_formed=false`) rather than silently removing it from the stream. The evaluator must return `BLOCKED` with exact `can_authorize_dispatch=false`, `independent_os_proof_verified=false`. The untouched independent instance continues to produce its ordinary well-formed source+parent write stream, which also remains nonauthorizing. Closing the duplicate after the registration change leaves the modified mask in force on the original FD; a real later byte restoration still generates native `IN_OPEN` there.

A separate disposable native Linux probe confirmed mask addition via alias, original-queue `IN_OPEN` and named parent write events. Final public source+parent dev/inode/mode, original fixture bytes, one-name inventory and native FD closure are checked. This is distinct from DEC-970/#1191's direct additive mask test, because the mask change originates through a **duplicated FD** while a truly independent observer's source mask remains unmodified.
