Native Linux `os.memfd_create(MFD_ALLOW_SEALING|MFD_CLOEXEC)` creates **anonymous PUBLIC** 23-byte bytes in RAM, not the protected annual inode. `fcntl(F_ADD_SEALS,F_SEAL_WRITE)` succeeds, the exact seal set is independently checked with F_GET_SEALS. A genuine direct `pwrite` and a newly requested writable MAP_SHARED `mmap.ACCESS_WRITE` both reject **EPERM** with original bytes unchanged and **no native anonymous source IN_MODIFY**. However **F_SEAL_WRITE does not imply F_SEAL_GROW or F_SEAL_SHRINK**. Genuine `ftruncate(length-1)` succeeds, permanently removes the last data byte and emits true anonymous source `IN_MODIFY`; `ftruncate(original_length)` also succeeds and emits another `IN_MODIFY`, but the restored length contains a **zero** where original final data had been. Exact original and final byte snapshots, source watch identity and final anonymous inode retirement `IN_DELETE_SELF/IN_IGNORED` are independently checked.

The critical security lesson is that a genuine kernel-enforced **write** seal, applied alone, is **not sufficient integrity confinement**: a size-changing syscall can still destroy data even while normal pwrite and writable mmap are rejected. Unlike prior named-source+parent /tmp tests, memfd is deliberately **anonymous** and has **no named original parent directory**; an isolated genuine inotify inode watch is created via `/proc/self/fd/<memfd>`. These are unrelated disposable PUBLIC resources and are explicitly **NOT independently OS-enforced no-write proof for protected annual files**.
