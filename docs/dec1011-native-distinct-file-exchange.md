# DEC-1011 — Exchange of two different regular-file inodes redirects writes

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict native Linux test/documentation child of DEC-1010/#1231, with generated public files only.

DEC-1010 demonstrates that `renameat2(RENAME_EXCHANGE)` on two names of the **same hardlinked inode** succeeds with **no move events**. DEC-1011 tests the opposite: two **different** public regular-file inodes, the original watched `sample` and `public-other`, are both watched on separate native WDs in the same inotify instance. Atomic exchange emits two distinct nonzero matched parent rename-cookie pairs and `IN_MOVE_SELF` on BOTH native file WDs without invalidating either inode watch. The test feeds each entire kernel move stream to the unchanged two-WD parser and evaluator, which must remain `well_formed=false` for the unexpected extra WD and `BLOCKED`, `can_authorize_dispatch=false`, `independent_os_proof_verified=false`.

Before swapping back, a genuine write to pathname `sample` now reaches the *other* inode WD, with parent `IN_MODIFY` named `sample`; the original source WD is quiet and the two-WD parser rejects that extra inode evidence. A genuine write to pathname `public-other` now reaches the *original sample inode* and original source WD, with parent named `public-other`. Both are real native content changes, and the source stream is nonauthorizing even when passed by itself. The swap-back restores pathname/inode placements but cannot erase the observed intermediate writes. The original bytes of both files are restored, disposable `public-other` is deleted with its own native `IN_DELETE_SELF` and `IN_IGNORED`, and source/parent dev/inode/mode, single-entry inventory, and FD closure are asserted.

The distinct-file native rename records and inode swaps were independently reproduced in a new public `/tmp` experiment. One new source-defined Linux method raises the stack to **661**.
