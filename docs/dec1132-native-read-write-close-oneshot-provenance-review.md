**Read-side versus write-side close:** Native `IN_CLOSE_NOWRITE` is generated on the close of a descriptor opened without write access, whereas `IN_CLOSE_WRITE` applies to a descriptor opened for writing, even if **no bytes were written**. Neither close event in isolation proves changed content. The original source or parent alternate one-shot registration is removed after its **first matching subscribed event** and emits IN_IGNORED. It cannot capture later actual content changes, even if it was originally subscribed to IN_MODIFY or IN_CLOSE_WRITE. This missing original event history is precisely why such intentionally unsafe registrations are test-only.

**Inode versus parent scope:** The source-specific no-byte events are unnamed on the original source inode registration. The parent-specific event carries the actual unrelated child basename. A read-only sibling close need not generate any source-file content event and does not imply a changed sample. The normal continuing helper deliberately omits CLOSE_NOWRITE from its mutation subscriptions and stays quiet on read-only opens/closes. This is **appropriate**; quiet in this single read-close operation is not independently OS-enforced protected no-write or a completed history of all file operations.

All three regressions use **genuine** Linux inotify descriptors and disposable PUBLIC source/sibling files. The normal source+parent helper `scripts/dec677_disposable_inotify_events.py::_start_watch` is unchanged and uses continuing mutation watches **without IN_ONESHOT**. In the separate later genuinely changed-byte write and restoring write controls, its native source and named-parent MODIFY/CLOSE_WRITE receipts remain positive and the unchanged evaluator returns exact **status=BLOCKED, can_authorize_dispatch=false, independent_os_proof_verified=false**. In the parent-sibling fixture, a two-name inventory deliberately does not meet the quiet admission contract; original/final byte equality never overrides observed mutations.
