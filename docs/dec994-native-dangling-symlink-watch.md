# DEC-994 — Native dangling symlink permits no-follow watch but not target-following

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit test/documentation child of DEC-993/#1214.

This generated-public Linux control creates a real dangling symlink `public-dangling-alias` pointing to a nonexistent public target in the same private `/tmp` folder. With the original sample+parent watches live, a create-only `inotify_add_watch` of this alias with normal symlink following returns genuine `-1/ENOENT`: the target does not exist. Create-only `IN_DONT_FOLLOW | IN_DELETE_SELF` against the same path succeeds, because the **symlink inode** does exist, and yields a third real WD on the same native inotify instance.

Actual unlink of the alias generates parent named `IN_DELETE` and link-WD `IN_DELETE_SELF` plus `IN_IGNORED`. The unchanged two-WD parser must reject the raw stream containing the extra link WD rather than filtering it into a false quiet interval; `_evaluate` returns `BLOCKED`, `can_authorize_dispatch=false`, `independent_os_proof_verified=false`. Afterwards, true public source writes and restoration still generate original source `IN_MODIFY` and parent named target `IN_MODIFY` even though the extra link watch is invalidated. The test checks final source/parent dev, inode, mode, original bytes, one-entry inventory, absence of the nonexistent target, and native FD closure.
