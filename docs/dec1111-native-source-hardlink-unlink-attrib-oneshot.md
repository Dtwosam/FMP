This native test first creates a real hard link `alias` to generated PUBLIC `sample` *before* installing any watches. Both names refer to the **same regular-file inode**, with link count two. A deliberately alternative **source-only** inotify one-shot registers `IN_ATTRIB | IN_MODIFY | IN_CLOSE_WRITE | IN_DONT_FOLLOW | IN_ONESHOT`; a wholly separate *continuing* normal source+parent watcher is also installed.

The test performs a real `os.unlink(alias)`: the original source one-shot gets **unnamed IN_ATTRIB** (source link count two to one) and then **IN_IGNORED**, removing it while the original watched source inode and `sample` pathname remain present. The independent continuing source+parent witness sees **unnamed source IN_ATTRIB and named parent IN_DELETE(alias)**. Recreating the exact hard-link relationship through `os.link(sample,alias)` restores link count two and original alias inode identity. The continuing watcher records another source IN_ATTRIB and named parent IN_CREATE(alias), but the original one-shot remains empty.

A genuine later changed-byte write and close **through alias** alters the original source inode. The continuing observer receives **unnamed source MODIFY/CLOSE_WRITE** and **named parent MODIFY/CLOSE_WRITE(alias)**, while the consumed source one-shot gets no further events despite those original subscriptions. A second genuine write **through sample** restores original bytes under *both* names; the continuing observer then receives source MODIFY/CLOSE_WRITE and named parent MODIFY/CLOSE_WRITE(sample). The test checks event parsing, unchanged evaluator exact `status=BLOCKED`, `can_authorize_dispatch=false`, and `independent_os_proof_verified=false`, final original bytes and inode/mode/link counts for source and alias, parent identity, bounded two-name inventory and native FD closure.

A standalone disposable native Linux syscall probe confirmed original IN_ATTRIB → IN_IGNORED on alias unlink, separate source IN_ATTRIB + named parent DELETE(alias), followed by source IN_ATTRIB + parent CREATE(alias) when the link returned, and real later alias/sample named write receipts with source inode write events only on the continuing witness. This is a **genuine namespace/link-count mutation** and is not described as a harmless read or a metadata-neutral operation. Unlike prior chmod/utime examples, the first event is caused by changing the number of names for the same inode without changing its file bytes.
