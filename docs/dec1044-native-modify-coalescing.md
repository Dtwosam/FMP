# DEC-1044 — Genuine writes coalesce into fewer inotify events without losing the watched inode

**DRAFT / NEVER MERGE / NEVER PROMOTE.** One strict native Linux regression test and documentation child of DEC-1043/#1264. All files are newly generated public disposable `/tmp` fixtures, and no protected or production operations are touched.

Create TWO actual independent kernel inotify instances on one public sample inode: a **source-only `IN_MODIFY` watcher** and an original **source+parent dual watcher**. Keep a single genuine writable sample FD open, then issue **SIX successful native `os.write` calls**, changing the first byte five times and restoring it on the sixth write. Neither watcher is drained between writes. The source-only instance receives **one** valid native `IN_MODIFY` because Linux **coalesces identical successive unread events**. The independent dual watcher receives actual source `IN_MODIFY` and named parent `IN_MODIFY` records for all six writes; each parent action separates successive source events in that instance's queue. Both observers refer to the same stable inode and final `sample.read_bytes()` again equals its original bytes.

With the writer still open, run three further genuine writes, draining **both** watchers after each write. The source-only watcher now reports one fresh `IN_MODIFY` per write. The writer's eventual close generates actual `IN_CLOSE_WRITE` only on the full dual watcher, not the source-only mask. The unchanged direct evaluator stays `BLOCKED` on the real source-only and dual streams, with exact `can_authorize_dispatch=false` and `independent_os_proof_verified=false`, even when public final bytes match. Original sample/parent device/inode/mode, public bytes, one-name inventory and every native source/writer FD closure are asserted.

A standalone disposable native Linux probe confirmed **six real writes → one source-only MODIFY vs twelve dual source+parent MODIFY records**, and per-write drains returned fresh source-only receipts. This is a separate failure mode from queue loss, watch mask replacement, unexpected WD identities and `FIONREAD=0`: **a nonzero native event count also need not equal the number of real writes**. Inotify is an event-observation API, not independently OS-enforced write confinement or immutable per-write provenance.
