**Critical Linux behavior on the probed disposable filesystem:** A genuine **`os.open(sample,O_RDONLY|O_TRUNC|O_CLOEXEC)`** of an existing writable ordinary PUBLIC source **truncates its original content to empty and size zero at open time**, even though the resulting file descriptor is opened read-only. The independent read witness registers native **source IN_OPEN**, the original unsafe source **MODIFY|CLOSE_WRITE|ONESHOT** consumes **IN_MODIFY→IN_IGNORED**, and the unchanged real continuing **source+original-parent mutation** helper receives **unnamed source IN_MODIFY and named parent IN_MODIFY(sample)**. Its evaluator receives the actual kernel receipt and exact **(BEFORE,b"")** data snapshots and returns **status=BLOCKED, can_authorize_dispatch=false, independent_os_proof_verified=false**.

The test then attempts actual `os.pwrite(readonly_fd,b"X",0)`, which **fails EBADF**, generating no additional source mutation event; the source nevertheless remains empty because truncation already happened during the earlier open. Closing the read-only descriptor emits separate positive read-witness **IN_CLOSE_NOWRITE**, **not** source CLOSE_WRITE on the continuing mutation helper, even though destructive file modification occurred during open. The read witness is closed before incidental source content verification.

Two genuinely valid subsequent O_WRONLY writes first put changed PUBLIC bytes into the empty file then restore original bytes, positively producing continuing source+named-parent MODIFY/CLOSE_WRITE while original ONESHOT stays removed; unchanged evaluator receives true native receipts and exact **(empty,changed)** and **(changed,BEFORE)** data snapshots. Original/final source and parent dev/ino/mode/nlink, restored contents and size, one-entry inventory and native descriptor cleanup are verified.

A separate actual native Linux syscall probe on freshly created PUBLIC /tmp files confirmed that O_RDONLY|O_TRUNC open generates **source and named-parent IN_MODIFY**, empties data and length, O_RDONLY close emits independently watched **IN_CLOSE_NOWRITE**, and a later pwrite on that read-only descriptor fails. This is sharply distinct from DEC-1197/#1418 **O_RDONLY without O_TRUNC**, where rejected pwrite leaves original bytes untouched, and DEC-1204/#1425 **O_WRONLY|O_TRUNC**, where open destroys bytes but later writable close yields CLOSE_WRITE. Whether O_RDONLY|O_TRUNC truncates is OS/filesystem-specific; this test reports the observed Linux semantics, not a universal guarantee.

An EBADF failure of a later data-write call or a read-only descriptor's CLOSE_NOWRITE is **not proof of independently enforced protected no-write** when open flags can already modify data.
