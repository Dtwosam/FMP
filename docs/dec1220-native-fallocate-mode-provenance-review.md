The core distinction is **where and how file contents, length and storage allocation change**. Successful allocations can create inotify MODIFY even when logical size or bytes do not change. KEEP_SIZE can allocate backing blocks beyond EOF. PUNCH_HOLE/KEEP_SIZE and ZERO_RANGE/KEEP_SIZE replace interior data with zeros **without changing file length**. COLLAPSE_RANGE deletes a middle span and shifts suffix left; INSERT_RANGE expands the file and shifts the suffix right, adding a zero-filled interior region. An O_RDONLY descriptor can reject fallocate requests, but a separate O_RDONLY|O_TRUNC open can nevertheless destroy data at open time on the probed Linux filesystem (#1427). CLOSE_NOWRITE does not retroactively prove the open path safe.
