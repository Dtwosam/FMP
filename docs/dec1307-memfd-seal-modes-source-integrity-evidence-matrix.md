## What these tests do and do not establish

- Native Linux sealing is a collection of **distinct operation-specific restrictions**. A rejected pwrite, writable mmap or ftruncate does not imply that every other mutating operation is denied. `F_SEAL_SEAL` only freezes the *seal set*; by itself it does not prohibit data mutation and can permanently prevent adding missing protections. `F_SEAL_FUTURE_WRITE` blocks future write grants but does **not** revoke an already writable MAP_SHARED map; `F_SEAL_WRITE` rejects EBUSY until such mappings are gone. Combining WRITE+GROW+SHRINK produces materially different integrity behavior than individual seals.
- Each executable regression checks the genuine anonymous memfd's `F_GET_SEALS` bitset and current `pread` bytes/size, native syscall denial errno or successful content changes, actual native anonymous inode inotify event-buffer receipts, final source **IN_DELETE_SELF/IN_IGNORED**, and FD/mapping cleanup. There is **no named original parent watch** for anonymous memfds, nor is any anonymous object asserted to be the protected annual inode.
- On these anonymous memfds, inotify records **IN_MODIFY for truncate but not in-place pwrite or MAP_SHARED stores**, even when original backing data changes, consistent with earlier disposable original file+named-parent tests #1485/#1512. Even a source watch that remained active cannot be converted to independent OS no-write enforcement or a positive annual dispatch authorization.
- Unlike the unchanged local `scripts/dec677_disposable_inotify_events.py::_evaluate` used in the *named PUBLIC /tmp file regressions*, these anonymous tests do not claim an `_evaluate` receipt for a nonexistent named parent. All authority flags and protected annual admission gates remain **BLOCKED**, not green.
