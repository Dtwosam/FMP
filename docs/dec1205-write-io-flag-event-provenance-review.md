**Critical distinctions:** A successful positive-length write syscall can leave file bytes unchanged (identical pwrite, identical copy) and still generate MODIFY. A zero-byte write may emit no MODIFY but the writable file description will emit CLOSE_WRITE on close even if content was never changed. The Linux O_APPEND file-description flag may override a pwrite positional offset of either 0 or 4096, and removing that flag on the live FD dynamically alters where the next write lands. Most importantly, opening a file with O_TRUNC **can destroy original bytes before any explicit data-write syscall**. Requested length, transferred byte count, descriptor flags, actual on-disk bytes and size, inode identity, and kernel notification receipt are separate evidence dimensions.
