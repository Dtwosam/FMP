**Key observations:** Source watches attach to inode identity, not a single immutable original pathname. A hardlink mutation through another directory can create source-inode MODIFY while original-parent named queue stays empty. A hardlink mutation inside the *same* parent names the **alias used**, not the canonical sample. Unlinking one pathname does not invalidate an inode watch if another hardlink survives. Duplicated writable file descriptors share an open file description, so the closing event occurs at the last release. Append flags do not relocate the requested fallocate range; they can redirect positional `pwrite` on that same Linux descriptor. Explicit ZERO_RANGE can grow logical length beyond EOF unless KEEP_SIZE is set. None of these imply kernel-enforced protected no-write.
