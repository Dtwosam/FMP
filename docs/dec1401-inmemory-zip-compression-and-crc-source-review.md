Six new in-memory tests (**1,278 proposed source-defined methods**). The DEC-1399 illustrative, **noninstalled** central-directory metadata checker now reports `UNREVIEWED_COMPRESSION_METHOD` unless a ZIP entry declares stored or deflated encoding; both BZIP2 and LZMA are rejected in synthetic test fixtures. This is a deliberately conservative *review policy example*, not a claim that either format is inherently unsafe or actually present in the protected archives.

A tiny generated STORED archive with a byte mutation in its data body still has a readable central directory and acceptable size metadata. `metadata_diagnostics` deliberately does not read member payloads and therefore reports no issue; an independent in-memory `ZipFile.read` triggers a CRC mismatch. The unmodified in-memory archive passes the same member-read CRC. **No archive is extracted to disk and no protected archive is opened.** This distinction shows that a metadata quota scanner is not a complete member-integrity checker. The actual checked-in workflow's *outer ZIP SHA-256 comparison before unzip* is a separate important control; these tests do not show it is bypassed, cannot establish source provenance, and do not imply the installed unzip skips CRC.
