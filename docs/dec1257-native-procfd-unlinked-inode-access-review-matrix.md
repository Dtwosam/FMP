## Invariants pinned by executable disposable Linux tests

1. All original public files were populated before registering unchanged original source+named-parent inotify via `scripts/dec677_disposable_inotify_events.py::_start_watch`. The original name is then **unlinked** while an O_PATH or O_RDONLY holder keeps the **same original inode** alive with `st_nlink=0`. True original source **IN_ATTRIB** and named parent **IN_DELETE(sample)** receipts occur at unlink. Original-parent inventory becomes empty.

2. While independently writable procfs-reopened descriptors exist, native Linux may still emit original **source IN_MODIFY** and original-parent **named IN_MODIFY(sample)** even though the original dentry has already been unlinked. The original inode watch survives until the last live file-description reference is released; **source IN_DELETE_SELF and IN_IGNORED** are checked at retirement, not inferred from filename disappearance.

3. An **isolated deliberately unsafe test-only source-only ONESHOT** watches for real first MODIFY, retires as MODIFY→IN_IGNORED and deliberately loses subsequent native events. The **unchanged continuing actual two-watch helper** captures genuine later MODIFY/CLOSE_WRITE and appropriate source retirement, while unchanged `_evaluate` always reports **status=BLOCKED**, **can_authorize_dispatch=false**, **independent_os_proof_verified=false** with real kernel bytes and true before/after source snapshots.

4. Access rights and file status flags are **specific to each newly reopened file description**. A prior O_PATH/O_RDONLY holder, rejected ftruncate/fallocate, or successful close of one description does not demonstrate that independently reopened O_RDWR, O_TRUNC or O_APPEND access is prevented. A valid independently OS-enforced protected no-write claim would require qualified independent proof of access denial across all relevant paths, names, processes and descriptors, not simply native event monitoring.
