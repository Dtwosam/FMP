Independently verified by native disposable Linux `/tmp` probe: create a populated single-linked original file, register actual original source+named-parent inotify and a deliberately unsafe source-only MODIFY|CLOSE_WRITE|ONESHOT, then acquire original O_PATH holder and unlink the final pathname. Genuine source IN_ATTRIB and original-parent named IN_DELETE(sample) occur. Reopen the nameless inode via `/proc/self/fd/<O_PATH_holder>` as a **read-only independent FD** and map it using **MAP_PRIVATE / `mmap.ACCESS_COPY`**. Changing the five first bytes of the private mapping causes genuine changed *memory-visible COW bytes*, but `os.pread` of the actual original detached inode still yields its **exact unchanged original bytes**. No native source/parent MODIFY is emitted.

Return the private mapping's bytes to original and now close **both the read-only procfs FD and the original O_PATH holder** while retaining the MAP_PRIVATE mapping. Neither close emits CLOSE_WRITE, DELETE_SELF or IGNORED: the mapping still retains a reference to the detached inode. With **no ordinary source FD or original pathname**, the copy-on-write mapping remains accessible and can be changed again to a different five-byte prefix; original data has not been written and native mutation queues stay empty. Only the **last MAP_PRIVATE unmap** emits original source **IN_DELETE_SELF and IN_IGNORED** and retires the kernel source watch, with **no CLOSE_WRITE**, since no writable mapping or file description modified original inode. The unsafe source ONESHOT remains armed until receiving only final IN_IGNORED.

MAP_PRIVATE COW can also outlive descriptors, but **never changes the original file bytes** and produces no CLOSE_WRITE.
