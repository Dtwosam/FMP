# DEC-1484 — Sparse-checkout disable is a reviewed precheckout action, not generic unreviewed source mutation

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit tests/docs child #1707 DEC-1483 at `3ec02e49c0ee6c699fc6efd530e2828ab23c2014`. Thirteen new source-defined unittest methods, **2,067 proposed methods**.

Read-only completed unprotected #1674 and recovered #1698 GitHub Actions job logs show that `actions/checkout` invokes `git sparse-checkout disable` just before `git checkout --progress --force refs/remotes/pull/N/merge` (following the immutable full-SHA fetch). This command can modify the working tree, but is part of the actual checked-out source establishment sequence. A naive blacklist of all extra `sparse-checkout` commands would incorrectly reject real successful runner logs. Conversely, ignoring all `sparse-checkout` commands could overlook a later source change.

This standalone pure-source reviewer requires exactly one **`git sparse-checkout disable`** action between the reviewed full immutable merge fetch and exact PR merge checkout, with strictly increasing UTC timestamps and no additional `sparse-checkout` action. Positive fixture timestamps come from independently read-only #1698 Phase3 and historical CI job logs. Negative tests reject missing/duplicated setup, alternative sparse-set commands, reordered stages, stale time and wrong PR ref. This explicitly models an **observed precheckout setup step**; it does not claim no post-checkout non-Git filesystem modifications, comprehensive submodule state proof, or an authenticated provider/runner OS audit.
