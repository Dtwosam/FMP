# DEC-1450 — Both required GitHub CI jobs must fetch the same merge commit

The DEC-1445–1448 reviewer established that one completed PR workflow's GitHub Actions runner fetched a temporary merge commit rather than directly checking out the PR head. A completed Phase3 run and a completed historical/general run can be associated with the same PR head SHA yet still fetch different temporary merge commits if the PR merge ref or base changes between independent checkouts. A result that verified only the historical workflow's runner checkout does not establish that both workflows tested an identical source tree.

This no-network, offline checker requires full separately obtained runner checkout records for **both** workflow IDs and exact run IDs, binds their actual full 40-hex Git fetch SHAs to one single PR merge commit object, checks correct source-tree identity and base/head parent order through DEC-1445, and requires distinct first-attempt completed-success runs. Duplicate/missing/extra runner logs, workflow-name impostors, altered workflow IDs/paths, mismatched run IDs and different tested merge commits fail closed. It does not obtain logs itself, authenticate remote GitHub events, or authorize an annual workflow.
