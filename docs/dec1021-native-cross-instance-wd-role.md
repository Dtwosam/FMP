# DEC-1021 — Equal numeric WDs can refer to different inode roles across independent instances

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit native Linux test/documentation child of DEC-1020/#1241.

DEC-1020 verifies independent inotify instances may have the same numeric source and parent WD values when registered in the SAME order. This new generated-public test deliberately reverses the order: the original instance registers **source then parent**, while a second real `inotify_init1` instance registers **parent then source** on the same disposable sample and directory. In the observed Linux kernel behavior, `primary_source_wd == second_parent_wd` and `primary_parent_wd == second_source_wd`. Passing the PRIMARY instance's source WD integer to `inotify_rm_watch(second_fd, primary_source_wd)` therefore actually removes the **second instance's PARENT watch**, yielding `IN_IGNORED` only in that second instance, while the first source+parent pair remains live.

A real transient public sibling creation/deletion is reported only by the first parent; the second instance sees none after its parent watch was invalidated. Actual changed-byte writes and restoration still reach source WDs of both instances, but named parent sample modifications appear only on the first.
