**The byte-count boundary is real.** A requested positive count is not a claim that any bytes were transferred when the source position or explicit offset lies beyond EOF. Linux native ACCESS remains quiet for a true zero transfer in these observed controls. An actual in-range transfer produces source ACCESS on the donor inode even when the copying is performed in the kernel rather than with userspace read/pread. Source READ events and destination WRITE events belong to **different inodes** on file-to-file `copy_file_range`; they must be captured on separate identities rather than conflated as one content-change receipt.

**Events do not exhaust all operations.** The earlier DEC-1157/#1378 read-only mmap regression confirms process access to mapped source bytes without native IN_ACCESS. DEC-1158/#1379 and DEC-1159/#1380 confirm writable MAP_SHARED mapped stores can change file bytes without native IN_MODIFY at store time, while later CLOSE_WRITE may occur at final writable file reference release. DEC-1160/#1381 confirms a private COW memory change leaves original source bytes unchanged. Therefore no quiet interim inotify queue is independent OS-enforced evidence that no write took place.

**First event and descriptor lifetime remain separate.** In zero-transfer controls the intentionally unsafe IN_ACCESS|ONESHOT remains active. Genuine positive reads consume it as IN_ACCESS→IN_IGNORED. Eventual ordinary O_RDONLY file descriptor close may independently emit IN_CLOSE_NOWRITE on a continuing read witness; that is not itself proof of any source-byte mutation. Later genuine ordinary changed-byte and restoring writes are separately captured as normal continuing source and named-parent MODIFY/CLOSE_WRITE and evaluated by the unchanged `_evaluate`, which remains exact **status=BLOCKED, can_authorize_dispatch=false, independent_os_proof_verified=false**.
