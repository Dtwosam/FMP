# DEC-1010 — RENAME_EXCHANGE of two hardlink names to the same inode is a no-op

**DRAFT / NEVER MERGE / NEVER PROMOTE.** Strict one-commit generated-public Linux regression/documentation child of DEC-1009/#1230.

DEC-1002/#1223 establishes that ordinary `renameat2(flags=0)` between two hardlink names on one regular-file inode succeeds as a no-op, whereas `RENAME_NOREPLACE` fails EEXIST. This complementary test invokes real native **`renameat2(RENAME_EXCHANGE)`** between the same two pathnames when both directory entries point to the **identical watched inode**. The syscall returns **0** while both hardlink names, dev/inode values and link count 2 persist, and the actual inotify queue stays **empty**: success does not necessarily mean that two inode-bearing directory entries moved.

Genuine later writes via each link are still observed by the original watched source WD as `IN_MODIFY` and by the parent under the real opened entry name. The unchanged evaluator is `BLOCKED`, with exact `can_authorize_dispatch=false` and `independent_os_proof_verified=false`. Removing the temporary alias produces native parent `IN_DELETE` and source `IN_ATTRIB`, restoring link count 1. Original public bytes, source/parent dev/inode/mode, single-entry inventory and FD closure are checked. A separate disposable Linux syscall/event probe confirmed the same-inode exchange no-op and zero native move receipts.
